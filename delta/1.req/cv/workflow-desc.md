# CV 流程说明

- 状态：已细化
- 权威需求：[../../SRS/SRS.md](../../SRS/SRS.md)
- 用例入口：[usecase-desc.md](usecase-desc.md)
- 流程图：[workflow.puml](workflow.puml)

## 1. 流程边界

本域包含四条业务流程：CV 导入确认、通用/岗位定制评审、建议决策与版本生成、敏感对象手动删除。PDF/DOCX 解析器和 AI provider 的具体实现均留待设计阶段；需求只约束能力、状态和失败语义。

## 2. WF-CV-01 导入与文本确认

**关联用例：** UC-CV-001、UC-CV-002。

1. 用户选择 PDF/DOCX。
2. 系统执行文件类型、可读性和安全校验。
3. 校验失败则拒绝导入，不产生可用对象。
4. 校验通过后先可靠保存原文件，再创建待确认版本。
5. 系统调用文本提取器：
   - 完整：保存提取文本，状态 `CONFIRMATION_REQUIRED`；
   - 疑似不完整：保存文本与诊断，状态 `CONFIRMATION_REQUIRED`；
   - 失败/扫描件：状态 `EXTRACTION_FAILED`，明确 v1 无 OCR，允许手工录入。
6. 用户预览、修正或补录纯文本。
7. 用户确认后形成不可变文本快照，状态 `CONFIRMED`；暂不确认则不可评审。

**失败与恢复：**

- 保存原文件失败：回滚本次导入，不留下声称可用的 Document/Version。
- 提取失败：保留原文件与失败诊断，可重试或手工录入。
- 确认保存失败：保留用户输入供重试，不改变最近一次已确认内容。

## 3. WF-CV-02 评审

**关联用例：** UC-CV-003、UC-CV-004、UC-CV-007。

1. 用户选择已确认 CV 版本。
2. 用户选择：
   - `GENERIC_HEALTH`：不需要 Job；
   - `TAILORED_TO_JOB`：必须选择 Job 并固定 JD 快照。
3. 系统创建评审请求；**始终**先运行 [local-review-rules.md](local-review-rules.md) 本地规则。
4. 若需外部 AI 增强：
   - provider 抽象必须已配置并启用；
   - 查询[全局 AI 同意注册表](../ai-consent.md)中相关 `dataCategory` 为 `GRANTED`；
   - 展示本次发送范围，允许脱敏或取消；
   - 计算 provider、model、输入版本、提示版本构成的缓存键。
5. 缓存命中则记录命中并复用输出；未命中则执行外部调用并记录完整调用元数据。
6. 系统验证输出的结构与事实约束，合并本地与 AI 建议（若有）。
7. 每条建议展示目标原文、问题、依据、建议修改，并等待用户决定。

**边界与失败：**

- AI 默认关闭或同意缺失：**仅**运行本地规则；岗位定制评审不依赖 AI。
- Provider 失败：评审技术状态 `FAILED`，允许重试，原 CV 和既有结果不变。
- AI 输出疑似引入新事实：建议标记 `FACT_CONFLICT`，不可接受。
- Job/JD 不可用：岗位定制评审不得启动；通用评审不受影响。

## 4. WF-CV-03 建议决策与版本生成

**关联用例：** UC-CV-005、UC-CV-006。

1. 用户逐项选择 `ACCEPTED`、`REJECTED` 或 `DEFERRED`。
2. 系统独立保存每项决定；AI 不得代替用户决定。
3. 用户选择创建新版本时，系统只收集当前 `ACCEPTED` 且无事实冲突的建议。
4. 系统检测同一文本范围冲突并生成结构化文本预览。
5. 用户确认后，新建以源版本为父版本的不可变 `CVVersion`，记录应用建议集合。
6. 用户可复制结构化文本；v1 不生成 PDF/DOCX，不提供富文本编辑。

**边界与失败：**

- 没有接受项：禁用创建操作。
- 拒绝和暂缓项：均不应用；暂缓项仍可后续决定。
- 生成失败：不创建半成品，不改变源版本和建议决定。
- 历史决定改变：不得反向修改已创建版本。

## 5. WF-CV-04 AI 同意生命周期

1. 初始时所有外部 AI provider 均为禁用。
2. 用户启用 provider 不等于同意发送全部数据。
3. 系统按数据类别（如 CV 文本、Job/JD、Profile）分别记录同意。
4. 同意可在后续同类调用中复用，但每次调用前仍展示实际发送范围并允许取消/脱敏。
5. 用户撤销某类别后，所有后续包含该类别的调用立即被阻止。
6. 历史调用保持可审计，直至其对应敏感对象被用户手动删除。

## 6. WF-CV-05 敏感对象删除

**关联用例：** UC-CV-008。

1. 用户选择删除一个 `CVDocument`。
2. 系统计算并展示影响：原文件、提取文本、全部版本、评审、建议、AI 调用内容/缓存及跨域引用。
3. 用户取消则流程结束且无变化。
4. 用户二次确认后，系统执行幂等的级联硬删除。
5. 删除成功仅保留无内容审计事件；删除不完整则明确报告剩余项并允许重试。

## 7. 状态与技术运行状态

### 7.1 CVVersion 业务状态

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `EXTRACTION_FAILED` | 无可用提取文本 | 重试、手工录入、删除 |
| `CONFIRMATION_REQUIRED` | 有待确认/修正文本 | 编辑、确认、删除 |
| `CONFIRMED` | 不可变事实快照 | 通用评审、岗位评审、复制、派生、删除 |

### 7.2 CVReview 业务状态

| 状态 | 含义 |
|---|---|
| `REQUESTED` | 已固定输入，待执行 |
| `RUNNING` | 正在本地检查或外部调用 |
| `COMPLETED` | 已形成可展示建议 |
| `FAILED` | 本次运行失败，可重试 |
| `CANCELLED` | 用户在发送前取消 |

### 7.3 技术状态与业务状态分离

- Provider 超时、缓存命中、重试次数属于 `AIInvocation` 技术状态，不改变 CV 业务事实。
- 建议的 `FACT_CONFLICT` 是可执行性标志，不等同于用户的接受/拒绝/暂缓决定。
- 文件删除运行状态必须独立记录；只有全部目标均已删除才可报告成功。

## 8. 流程级验收

- 任意失败路径均不覆盖原文件、已确认文本或历史版本。
- 未确认文本不能进入评审；未同意的数据不能发送外部。
- 通用评审与岗位评审使用不同类型，后者固定 JD 快照。
- 新版本只应用接受项，且可追溯到源版本和建议。
- 数据无自动过期；手动删除前预览影响，成功后只保留无内容审计。
