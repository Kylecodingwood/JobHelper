# Profile 用例说明

- 权威需求：[../../SRS/SRS.md](../../SRS/SRS.md)

- 对应需求：`FR-PRO-001`～`FR-PRO-008`

## `UC-PRO-001` 首次配置求职档案

- **优先级**：Must
- **参与者**：求职者
- **触发条件**：本地应用首次启动，或尚无可用 `Profile`。
- **前置条件**：应用可访问本地存储；系统中不存在第二个用户档案。
- **输入**：学校、专业、课程起止日期；目标岗位、职级、地点；语言熟练度；技能与项目/实习/工作经历；一条或多条工作许可记录（国家、许可类型、有效期、每周工时上限），可包含未来 `Stamp 1G`。
- **主流程**：
  1. 系统按教育、工作许可、目标与证据四组展示表单及字段用途。
  2. 用户录入至少一个 `EducationPeriod`、一个 `TargetRole` 和当前或未来的 `WorkAuthorization`。
  3. 系统校验必填项、日期区间、工时及重复项，并展示归一化结果。
  4. 用户确认保存。
  5. 系统原子化保存 `Profile` 及其子实体，并记录 `profileVersion`。
  6. 系统创建 `PENDING` 的 `RecomputeRequest`（含 `ROADMAP` 时展示模板/锚点/任务预览）；Roadmap 仅在用户预览确认后生成，不自动改变任何用户决定。
  7. 活动 `TargetRole.roleName` 作为 Job 搜索词默认值登记（用户可在 Source 设置覆盖）。
- **替代/错误流程**：
  - A1：用户暂不提供可选经历或技能证据，系统允许保存并标记资料缺口。
  - E1：结束日期早于开始日期、工时为负数或必填字段为空时，系统定位错误且不保存无效版本。
  - E2：本地写入失败时，系统保留当前输入供重试，不产生半成品档案。
- **后置条件**：存在唯一有效 `Profile`；其聚合内数据可用于 Roadmap、Gate 与 Rank；存在待用户确认（含 Roadmap 预览）的重算请求。
- **业务规则**：
  - `BR-PRO-001`：v1 仅允许一个本地 `Profile`，无账号、租户或共享档案。
  - `BR-PRO-002`：工作许可必须按时间线保存，当前许可与未来 `Stamp 1G` 不得压缩为单一布尔值。
  - `BR-PRO-003`：保存 Profile 不等于授权外部 AI 使用其字段。
  - `BR-PRO-010`：首次合法保存后，`ROADMAP` 重算须先展示预览，用户确认后才生成基线 Roadmap。
- **关联 FR**：`FR-PRO-001`、`FR-PRO-002`、`FR-PRO-003`、`FR-PRO-004`、`FR-PRO-006`
- **验收场景**：
  - Given 无档案，When 用户录入课程日期、目标 `Graduate Software Engineer`、Dublin、技能经历、当前许可及未来 `Stamp 1G` 并确认，Then 系统保存唯一档案与完整许可时间线，并产生待确认的重算建议。
  - Given 毕业日期早于入学日期，When 用户保存，Then 系统拒绝保存并指出日期错误。

## `UC-PRO-002` 更新求职档案

- **优先级**：Must
- **参与者**：求职者
- **触发条件**：用户在 Profile 页面编辑已有档案。
- **前置条件**：存在有效 `Profile`。
- **输入**：任一 Profile 字段修改，以及教育、目标、许可、技能或经历的新增、编辑、删除。
- **主流程**：
  1. 系统加载当前 `profileVersion` 和字段用途标识。
  2. 用户编辑数据并提交。
  3. 系统校验修改并计算受影响领域（Roadmap、Job Gate、Job Rank）。
  4. 系统展示差异及影响摘要。
  5. 用户确认保存；系统创建新 `profileVersion`。
  6. 系统保留既有用户决定，登记 `PENDING` 的 `RecomputeRequest`；含 `ROADMAP` 时须预览确认后才合并重算。
- **替代/错误流程**：
  - A1：修改不影响派生结果时，系统保存且不创建重算请求。
  - A2：用户取消确认时，不保存修改。
  - E1：提交基于过期版本时，系统拒绝覆盖并要求刷新后重新确认。
- **后置条件**：有效修改已保存；影响范围可追溯；既有 Job 决定、任务完成记录和覆盖理由不变。
- **业务规则**：
  - `BR-PRO-004`：影响分析必须在保存确认前可见。
  - `BR-PRO-005`：Profile 修改只能建议重算，不能静默执行或覆盖决定。
- **关联 FR**：`FR-PRO-001`～`FR-PRO-006`
- **验收场景**：
  - Given 已有目标地点 Dublin，When 改为 Dublin 与 Cork，Then 系统展示 Gate/Rank 影响，保存后保留已有 Job 状态并创建待执行重算请求。

## `UC-PRO-003` 确认并执行影响重算

- **优先级**：Must
- **参与者**：求职者
- **触发条件**：Profile 保存后存在 `RecomputeRequest`，或用户手动选择重新计算。
- **前置条件**：存在有效 Profile 版本和至少一个受影响领域。
- **输入**：目标 `profileVersion`、重算范围（Roadmap、Gate、Rank）。
- **主流程**：
  1. 系统展示变更来源、目标版本、影响范围及不会被覆盖的数据；`ROADMAP` 范围须展示模板/锚点/任务预览。
  2. 用户选择范围并明确确认（含 Roadmap 预览确认）。
  3. 系统对所选范围执行确定性重算并记录状态。
  4. 系统展示新增、更新、冲突与失败摘要。
  5. 用户决定保持或采纳派生建议；原用户决定始终保留。
- **Roadmap 合并语义**（与 Roadmap 域一致）：
  - 更新当前 `ACTIVE` Roadmap，不新建并行 Roadmap。
  - 仅重算系统生成且未完成的任务。
  - 保留：用户创建任务、已完成/已归档任务、用户编辑、置顶、依赖覆盖（`DependencyOverride`）。
- **替代/错误流程**：
  - A1：用户推迟重算，请求状态置为 `DEFERRED`（非保持 `PENDING`）。
  - E1：部分领域重算失败时，成功结果可保留，失败范围标记 `Failed` 并可重试。
  - E2：目标 Profile 版本已过期时，系统终止该请求并要求基于最新版本重新确认。
- **后置条件**：请求处于 `Completed`、`PartiallyFailed`、`Failed` 或 `Deferred`；结果可追溯到 Profile 版本；无用户决定被覆盖。
- **业务规则**：
  - `BR-PRO-006`：重算必须由用户显式触发。
  - `BR-PRO-007`：重算幂等；同一 Profile 版本与范围的重复执行不得重复创建派生对象。
  - `BR-PRO-008`：Roadmap 用户编辑/完成、Job Decision 等用户决定优先于重算结果；Roadmap 合并遵循上述语义。
- **关联 FR**：`FR-PRO-005`
- **验收场景**：
  - Given Profile 的许可日期已更新且请求为 `PENDING`，When 用户只确认 Gate 重算，Then 仅 Gate 结果更新，Roadmap 与 Rank 保持不变，所有 Job Decision 保留。
  - Given 用户推迟 Roadmap 重算，When 关闭预览，Then 请求为 `DEFERRED` 而非 `PENDING`。
  - Given 已有 Roadmap 含用户创建任务与已完成任务，When 用户确认 Profile 触发的 Roadmap 重算，Then 仅系统生成未完成任务被更新，用户任务与完成记录保留。

## `UC-PRO-004` 查看档案用途与敏感性

- **优先级**：Should
- **参与者**：求职者
- **触发条件**：用户查看或编辑 Profile。
- **前置条件**：应用已启动。
- **输入**：无。
- **主流程**：
  1. 系统标识每组字段是否用于 Roadmap、Gate、Rank。
  2. 系统标识个人经历、许可等敏感字段。
  3. 系统说明本地保存原则，并明确外部 AI 使用需按[全局 AI 同意注册表](../ai-consent.md)敏感数据类别另行授权且可撤销。
- **替代/错误流程**：无 Profile 时仍显示字段说明，但不展示个人值。
- **后置条件**：不改变任何数据或同意状态。
- **业务规则**：`BR-PRO-009`：用途说明不得被解释为 AI consent。
- **关联 FR**：`FR-PRO-006`
- **验收场景**：
  - Given 用户打开工作许可字段说明，Then 系统显示其用于 Gate/Roadmap、属于敏感数据，且未获得 AI 调用许可。

## `UC-PRO-005` 每周本地自动备份

- **优先级**：Must
- **参与者**：求职者（知情）、本地调度
- **触发条件**：默认每周一次（具体时刻与保留份数在设计阶段确定）；应用运行且存储可写。
- **前置条件**：存在可备份的本地数据存储。
- **输入**：无（自动）；可选用户配置的备份目录（若设计支持）。
- **主流程**：
  1. 调度器在周期到达时触发完整本地备份（含 Profile、Job、CV、Behavioral、Roadmap、Action 等域数据）。
  2. 系统写入可恢复备份包并记录备份元数据（时间、版本、校验和；不含明文敏感字段于普通日志）。
  3. 失败时记录诊断并可在下次周期或手动导出时补救；不删除用户主库。
- **后置条件**：至少一份可识别周期的备份存在（成功时）；主库不受影响。
- **业务规则**：`BR-PRO-010`：备份为完整快照；默认启用 weekly；保留策略在设计 ADR 量化。
- **关联 FR**：`FR-PRO-008`；SRS 第 11 节（备份）
- **验收场景**：Given 主库有 Profile 与 Job 数据，When weekly 备份成功，Then 存在带时间戳的可恢复备份且主库可读。

## `UC-PRO-006` 手动完整导出

- **优先级**：Must
- **参与者**：求职者
- **触发条件**：用户选择“导出全部数据”。
- **前置条件**：应用可访问本地存储与用户选定导出路径。
- **输入**：导出目标位置；可选加密口令（设计阶段）。
- **主流程**：
  1. 系统说明导出范围与敏感内容提示。
  2. 用户确认路径并发起导出。
  3. 系统生成完整可移植导出包（格式在设计阶段定义）。
  4. 系统报告成功或失败，不修改主库。
- **后置条件**：用户获得完整导出文件；同意与删除状态随包导出策略在设计阶段明确。
- **业务规则**：`BR-PRO-011`：导出须覆盖全部用户域数据，不得仅 Profile 子集。
- **关联 FR**：`FR-PRO-008`；SRS 第 11 节（导出）
- **验收场景**：When 用户确认导出，Then 得到可在 UC-PRO-007 中使用的完整包。

## `UC-PRO-007` 从备份或导出恢复

- **优先级**：Must
- **参与者**：求职者
- **触发条件**：用户选择从 weekly 备份或手动导出包恢复。
- **前置条件**：存在有效备份/导出包；用户理解将覆盖或合并当前库（策略在设计阶段二选一并明确预览）。
- **输入**：备份/导出包引用；恢复模式（覆盖/合并，若支持）；二次确认。
- **主流程**：
  1. 系统校验包完整性与版本兼容性并预览将影响的数据域。
  2. 用户二次确认恢复。
  3. 系统在一致性边界内恢复数据；失败时报告部分状态并支持重试。
  4. 恢复后触发必要的重算建议（Roadmap/Gate/Rank），不静默覆盖用户决定。
- **后置条件**：主库与包一致（按所选模式）；或恢复失败且状态可诊断。
- **业务规则**：`BR-PRO-012`：恢复前必须预览与确认；不得在无确认下覆盖生产库。
- **关联 FR**：`FR-PRO-008`；SRS 第 11 节（恢复）
- **验收场景**：Given 有效导出包，When 用户确认覆盖恢复，Then 恢复后 Profile 与 Job 数据与包一致且应用可启动。
